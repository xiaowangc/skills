## 1. 能力分类

把能力分成四类：

- 只读检索：数据库、文档、搜索和状态查询；
- 写操作：发送、更新、创建、删除、支付或控制设备；
- 计算与执行：代码、SQL、浏览器、文件系统和沙箱；
- 人类交互：澄清、批准、补充信息和接管。

每类能力采用不同权限、审批、隔离和审计策略。不要让“通用工具”跨越多个风险域。

## 2. 工具契约

工具表示用户或业务任务，不是底层 API 的机械镜像。优先暴露 `create_refund_request`，而不是把包含几十个可选字段的退款 API 原样交给模型。

每个工具定义：

- 清晰、唯一、面向动作的名称；
- 何时使用、何时不使用、前置条件和副作用；
- 简短参数列表、字段类型、约束、默认值和例子；
- 输入与输出 JSON Schema；
- 读取/写入的数据范围和敏感级别；
- 调用主体、代表的用户及所需授权；
- read-only、destructive、idempotent、open-world 等行为，但不把元数据提示当作策略；
- 超时、限流、重试、幂等键和补偿；
- 成功、业务失败、系统失败和可重试失败的结构化结果；
- 版本、所有者、SLA 和弃用策略。

Instructions 描述目标和业务规则，不重复工具说明，也不要硬编码会频繁变化的工具名。确有调用顺序或交互副作用时显式说明。

## 3. 输出与错误设计

工具输出默认简洁、结构化、可验证。大文件、大表、图像或长日志保存为 Artifact，只返回引用、摘要、大小、类型、有效期和访问规则。

错误信息同时服务运行时和模型，至少包含：

- 稳定错误码；
- 是否可重试及建议等待时间；
- 哪个输入或前置条件失败；
- 可安全采取的下一步；
- 不暴露密钥、内部堆栈或敏感数据。

工具返回内容是非可信输入。先校验 Schema，再做注入检测、敏感信息识别和内容净化，最后才进入模型上下文。

## 4. MCP 采用判断

适合 MCP：跨多个 Agent/宿主复用、运行时发现、第三方生态连接或需要统一工具接口。

不适合 MCP：简单内部调用、强事务一致性、极低延迟热路径，或组织尚无能力补齐身份、授权、观测和供应链治理。

生产采用时：

- MCP Server 和工具显式白名单；
- 固定 Server/包/工具定义版本或哈希；
- 工具清单变化触发重新审查，不静默继承新能力；
- Client/Gateway 检查语义重名和工具影子；
- 对 Tool、Resource、Prompt、Sampling、Elicitation 分别授权；
- 默认少用或禁用远程 Prompt；
- Sampling 与 Elicitation 必须可见、可拒绝，禁止索取敏感凭证；
- Roots 不是强安全边界，文件系统仍需沙箱和真实 ACL；
- 工具数量大时做可信的工具检索，但保护索引免受恶意 Schema 注入。

## 5. 威胁模型与控制

| 风险 | 典型后果 | 核心控制 |
| --- | --- | --- |
| Prompt/间接注入 | 覆盖指令、越权动作 | 数据/指令分离、输入净化、模型外策略、低信任规划区 |
| 动态能力注入 | Agent 静默获得新写权限 | 白名单、版本固定、变更批准、Gateway 过滤 |
| 工具影子 | 恶意工具抢占合法工具 | 命名/语义冲突检测、可信来源、敏感动作人工批准 |
| Confused Deputy | 借高权限服务越权 | 传播用户与 Agent 身份、受众/范围绑定凭证、每次动作授权 |
| 数据外泄 | 敏感内容进入工具或回答 | 最小上下文、字段级标注、DLP、出口控制、输出净化 |
| 记忆投毒 | 后续会话持续受污染 | 来源、置信度、隔离、写入过滤、可删除/重建 |
| 凭证泄漏 | 密钥进入 Prompt/Trace | Side channel 注入、Secret Manager、日志脱敏、短期凭证 |
| 任意代码/浏览器 | 横向移动或破坏 | 沙箱、网络/文件白名单、资源限额、审批与录制 |

每个运行主体分开建模：用户身份、Agent 身份、运行服务身份。Agent 只能使用与当前用户授权交集内的委派权限，不能用平台的宽权限替代用户权限。

## 6. 高风险动作

高风险包括付款、删除、对外发送、生产变更、账户/权限修改、隐私数据披露和物理设备控制。统一采用：

1. Agent 生成结构化行动提议和依据；
2. 确定性策略引擎校验权限、金额、范围和数据分类；
3. 向责任人展示影响范围和不可逆性，取得显式批准；
4. 使用短期、最小范围凭证执行；
5. 验证实际结果，不以“工具调用成功”代替业务成功；
6. 写入不可抵赖审计记录；
7. 在可能时提供补偿或撤销。

为工具或能力域设置独立熔断器，发生攻击或异常成本时可立即停用，而无需关闭整个 Agent。

## 7. 审查清单

- 工具是否代表一个清晰任务而不是完整 API？
- 读与写、低风险与高风险是否分离？
- 授权是否绑定用户、Agent、资源和动作？
- 所有外部内容是否按非可信数据处理？
- 重试会不会产生重复付款、消息或写入？
- 工具错误能否指导安全恢复？
- 工具输出是否会淹没上下文？
- MCP 清单变化、依赖升级和供应链风险如何控制？
- 是否能立即撤销单个工具权限并追溯所有调用？
