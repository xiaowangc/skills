## 1. 生产差距

Demo 证明“在理想输入下偶尔能工作”；生产系统必须证明在真实负载、错误、攻击、权限和成本约束下持续可控。生产工作通常集中在基础设施、安全、验证和运营，而不是 Prompt 本身。

在立项时就指定：产品/业务 Owner、风险 Owner、领域专家、Agent/AI 工程、平台/安全、数据与运维责任。小团队可以一人多岗，但责任不能缺位。

## 2. 版本与环境

同时版本化：

- 业务契约与 Agent 清单；
- Instructions、示例和 Prompt 模板；
- 模型和推理参数；
- 工具、MCP Server、Schema 和权限策略；
- Workflow 与状态/记忆 Schema；
- Guardrail、Judge Rubric 和评测数据；
- 运行镜像、依赖与基础设施配置。

开发、测试、Staging、生产分离。使用同一不可变 Artifact 从 Staging 晋升生产，避免“重新构建后上线”。密钥在运行时注入，不进入仓库、Prompt 或镜像。

## 3. 评测门禁流水线

按成本从低到高构建漏斗：

1. PR/CI：静态校验、Schema、单元测试、依赖/安全扫描、快速核心评测；
2. 合并后 Staging：完整行为评测、远程集成、负载、故障注入、红队和内部试用；
3. 生产批准：风险 Owner 审查差异、阈值、已知风险和回滚条件；
4. 发布后：在线指标与离线评测共同验证。

初期可要求 PR 附人工运行的评测报告；成熟后把阈值自动化。任何模型、Prompt、工具、记忆或安全策略变更都应触发相应回归集。

## 4. 安全发布

- Canary：从小流量开始，监控异常工具调用、安全和业务指标；
- Blue-Green：保留完整旧环境，快速切换；
- A/B：在有足够样本和明确 KPI 时比较真实业务效果；
- Feature Flag：独立控制高风险能力和用户范围。

发布计划写明：观察窗口、晋级条件、停止条件、自动/人工回滚触发器、状态/记忆兼容和数据回填策略。

## 5. 运行控制

为每个任务设置：最大模型调用数、工具调用数、Token、金额、墙钟时间、并发和重试。超过预算时应安全终止、输出已完成内容或转人工，不得无限循环。

Agent 服务尽量无状态，Session/Memory/Artifact 外置。长任务采用持久化 Workflow 或队列，支持暂停、恢复、取消和幂等重放。工具调用用指数退避，但前提是幂等或具备去重/补偿。

运行手段包括：缓存、并行、模型路由、批处理、限流、背压、熔断、降级到只读/人工模式，以及按租户的成本配额。

## 6. 事件响应

采用 Contain → Triage → Resolve：

1. Contain：工具级 Feature Flag/熔断立即停止危害，撤销凭证或切换只读；
2. Triage：保存脱敏 Trace、识别受影响用户/资源、进入人工队列；
3. Resolve：修复策略、Prompt、工具或数据；补充失败样本；通过完整流水线和灰度发布。

预先演练：Prompt 注入、越权写入、数据泄漏、模型/工具供应商故障、成本失控、记忆污染和跨 Agent 死锁。

## 7. 持续演进

AgentOps 闭环：

- Observe：日志、Trace、业务/质量/安全指标和用户反馈；
- Act：告警、限流、熔断、人工接管和快速回滚；
- Evolve：聚类失败、复现、加入评测集、修复、重新评测和安全发布。

禁止运行时 Agent 直接修改生产 Instructions、工具或权限。自优化结果作为候选变更进入离线沙箱和正常发布流程。

## 8. 生产就绪等级

| 等级 | 可接受状态 | 不可声称 |
| --- | --- | --- |
| 探索 | 人工测试、假数据、无外部写 | 可靠、可扩展、安全上线 |
| 受控试点 | 有边界用户、基础评测、人工审批、可回滚 | 全自动、企业级 SLA |
| 生产 | 完整契约、门禁、观测、权限、事件响应和 SLO | 无需持续运营 |
| 规模化 | 多租户治理、注册/复用、容量和成本控制、跨 Agent Trace | 自治无边界 |

设计结论必须指出当前等级、目标等级、差距和每项差距的验证证据。
