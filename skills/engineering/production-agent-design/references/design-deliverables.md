## 1. 快速方案

适合早期讨论，按以下结构输出：

1. 推荐结论：是否需要 Agent，推荐自治级别和核心理由；
2. 业务契约：用户、触发、目标、成功/失败、不做什么；
3. 最小架构：模型判断节点、确定性 Workflow、工具、状态和人工节点；
4. 三个最高风险及控制；
5. 验证计划：最小评测集、指标和试点门槛；
6. 未决问题与下一步。

## 2. 完整设计

### 2.1 执行摘要

- 业务问题与价值；
- 推荐方案和目标生产等级；
- 核心取舍；
- 关键阻塞项。

### 2.2 业务任务契约

- 主要用户/调用方；
- 任务触发和输入；
- 期望业务结果与输出 Schema；
- 范围外事项；
- 成功、部分成功、拒绝和失败；
- 业务/风险 Owner；
- SLA、成本和合规约束。

### 2.3 Agent 适用性与自治

- 为什么普通软件不足；
- 哪些节点需要模型判断；
- 选定自治级别；
- 为什么不采用更高/更低级别；
- 单 Agent 或多 Agent 的证据。

### 2.4 架构与数据流

- 组件职责和信任边界；
- 端到端流程、状态与终止条件；
- Model/Tool/Workflow/Agent 的分工；
- Session、Memory、RAG、Artifact；
- 外部依赖、失败与降级；
- 版本和运行时边界。

### 2.5 工具与权限

使用工具表，标出读/写、敏感数据、身份、幂等、审批、审计和熔断。

### 2.6 上下文与记忆

- 上下文组成和 Token 预算；
- Session 保存与压缩；
- 记忆主题、范围、来源、生成/检索/删除；
- RAG 权威来源和刷新；
- 隔离与隐私。

### 2.7 安全与治理

- 威胁模型；
- 身份和授权链；
- 模型外策略；
- 高风险审批；
- 沙箱、凭证和数据控制；
- 审计、应急和责任边界。

### 2.8 质量与评测

- 四类质量目标；
- Dataset 分层和样本来源；
- 端到端与轨迹 Rubric；
- 自动 Judge 与人工校准；
- 发布阈值和基线；
- 线上反馈进入回归集的流程。

### 2.9 生产与运营

- CI/CD 与环境；
- 灰度和回滚；
- SLO、预算、指标和告警；
- 事件响应；
- Observe → Act → Evolve。

### 2.10 路线、决策与未知

- 阶段目标和退出证据；
- ADR/关键决策；
- 假设、未知和负责人；
- 已接受风险及到期复审日期。

## 4. 分阶段路线

- Phase 0 业务验证：证明任务、数据和 KPI 成立；不接高风险写操作。
- Phase 1 离线原型：建立端到端流程和首版 Golden Set；输出可复现基线。
- Phase 2 受控试点：真实只读数据或审批式写入；完善 Trace、预算和接管。
- Phase 3 生产上线：评测门禁、SLO、灰度、回滚和事件响应全部通过。
- Phase 4 规模化：按实际瓶颈引入多智能体、动态工具、注册中心和更复杂记忆。

每一阶段写明退出证据，不用“功能已完成”代替质量、安全和运营证据。

## 5. 设计评审结论

结论使用以下标签：

- 可进入下一阶段：所有硬门槛已有证据；
- 有条件通过：列出必须在下一门禁前关闭的问题、Owner 和验证方式；
- 不建议：任务不适合 Agent 或收益不足以覆盖风险；
- 未达到生产就绪：原型可继续，但缺失一个或多个硬门槛。

避免空泛的“建议加强安全/评测”。每条问题必须能落实为设计变更、证据或明确决策。
